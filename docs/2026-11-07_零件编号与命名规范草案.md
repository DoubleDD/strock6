# 零件编号与命名规范草案

> 状态：**草案，待用户确认；尚未成为强制规则**。
>
> 本文用于审查零件编号的规则、登记方式和落地顺序。当前不修改 `AGENTS.md`、FreeCAD 建模技能、参数表或任何 FCStd，也不预先分配正式零件号。
>
> 配套入口：[实施计划](2026-11-06_望远镜实施计划.md)、[参数表](2026-11-06_望远镜参数表.md)、[现有命名与文档规范](../wiki/project/命名与文档规范.md)。

## 1. 目标与适用范围

建立一套可人工阅读、可机器校验、可跨会话执行的零件编号制度，使零件号能够稳定连接：

**设计参数 → 零件登记表 → FCStd 源件 → 装配实例 → BOM／加工交付物。**

本规则适用于：

- 自制零件、外购示意零件和需要独立制造／采购／更换的零件；
- 装配文档的装配号；
- 零件在总装、参数表、BOM 和加工文件中的引用；
- 零件号的新增、停用、变更和回归检查。

本规则不替代以下现有体系：

- 参数 ID 仍由参数表管理；
- 任务 ID 仍由实施计划管理；
- FCStd 文件名、FreeCAD 内部 `Name` 和参数 `Alias` 仍按原规则维护；
- 草图、基准和特征继续使用中文自描述 `Label`，不逐一分配零件号。

**零件号、参数 ID、任务 ID 是三个独立命名空间，不得互相推导或混用。**

## 3. 编号语法

### 3.1 基本格式

```text
<大模块码>-<两位序号>
<大模块码>-<小模块码>-<两位序号>
```

统一使用 ASCII 大写字母、半角连字符和两位十进制数字。格式校验正则：

```regex
^[A-Z]{1,2}(-[A-Z]{2})?-[0-9]{2}$
```

合法示例：

```text
ZJ-XH-01
D-01
```

非法示例：

```text
ZJ-XH-1       # 序号不足两位
ZJ-XH-001     # 序号超过两位
ZJ-XH-01A     # 序号混入字母
ZJ_XH_01      # 使用下划线
zj-xh-01      # 使用小写
ZJ-XH-01-L    # 把左右件或实例位置附加到零件号
```

补充限制：

- 序号从 `01` 开始，`00` 不用于正式零件或装配；
- 字母 `I`、`O` 不得进入模块码，避免与数字 `1`、`0` 混淆；
- 正则只检查外形，**不能替代封闭码表检查**；符合正则但未登记的码仍然非法；
- 不预留连续编号作为完成判据，停用造成的空号允许保留；
- 某段序号达到 `99` 后不得自行扩展位数，应停下并由用户决定新增小模块或调整规则。

### 3.2 三条禁令

1. **禁自编码**：不得绕过登记表自行拼造模块码、零件号或集合词。已登记模块内的新零件可按最小空闲序号分配，但必须先登记、后在模型和文档中使用；新增或修改模块码必须由用户确认。
2. **禁用 I／O**：模块码不得包含 `I` 或 `O`，不得用易混字符临时顶替。
3. **重号即停**：发现重号、一号多源件、同一路径多正式编号或编号与中文名不一致时，停止继续发号和批量回写，先报告冲突；不得静默改号覆盖。

| `GT` | GoTo | 预留，未启用 |

小模块码同样采用封闭登记，不得临时创造。当前仅把提案中的 `XH`（下环）列为待确认示例，不据此推定其他小模块码。

码表规则：

- 新模块、新小模块或新集合词必须先向用户申请；
- 预留码不等于已启用码，未登记对象不得使用；
- 模块码表达稳定的产品归属，不表达当前任务、设计者、材料、板厚或加工批次；
- 跨模块通用件归 `TY`，不能因在多个装配中使用而重复发号；
- 零件改变所属模块时是否保留原号按第 9 节处理，不为目录整齐而批量换号。

## 5. 零件号、装配号、实例号与文档类型

### 5.1 同种多件只用一个零件号

零件号标识一种零件定义，不标识每一件实物。相同几何、材料、工艺和接口的重复件共用一个编号，数量放在装配或 BOM 的数量列。

例如 8 根相同铝杆只使用一个零件号；装配中的实例可写为：

```text
HJ-01#01
HJ-01#02
...
HJ-01#08
```

其中 `#01` 是实例序号，**不属于零件号**，不得写入零件号登记表。实例序号用于装配记录、试装和故障定位，不改变源件映射。

以下情况不得用实例后缀掩盖零件差异：

- 左右镜像件不能互换；
- 孔位、长度、材料或加工处理不同；
- 同位置使用但制造定义不同。

上述情况应分别登记零件号。

### 5.2 零件与装配分开登记

- **零件号**：发给独立制造、采购、更换或运动的零件源件。
- **装配号**：可复用同一编号语法，但登记类型必须标为“装配”，不能与零件混作 BOM 数量统计。
- **实例号**：只在装配上下文出现，不单独建立 FCStd 源件映射。

### 5.3 并非每份 FCStd 都领零件号

当前仓库实际有 **26 份现行 FCStd**，包括总装、模块装配、零件源件、总体骨架、契约、整板排版和试验文档。后续盘点应以当时文件为准，不能继续沿用“现有 24 个”的旧数量。

| 文档类型 | 是否分配零件号 | 登记方式 |
| --- | --- | --- |
| 单一零件源件 | 是 | 编号与主 FCStd 路径一一对应 |
| 装配文档 | 分配装配号，不分配零件号 | 登记装配号、路径和组成范围 |
| 总体骨架 | 否 | 只登记路径和文档类型 |
| `Interfaces` 契约层 | 否 | 只登记路径和文档类型 |
| 整板排版文档 | 否 | 登记路径和包含的零件号清单 |
| 试片／套合试验等多件文档 | 不为文档整体发零件号 | 登记试验文档；需要独立加工的零件再逐项登记 |
| 历史零件＋装配混合文档 | 不为整体虚构单一零件号 | 标记过渡态，逐步登记实际零件根对象 |

因此，“一一对应”应准确理解为：**每个正式编号只对应一个主源件或装配文档，每个已编号主文档只对应一个正式编号。** 对不领号的文档必须显式记录类型，不能用重号来凑齐文件清单。

STEP、DXF、STL 等是同一主模型的导出物，不另占源件编号；`backup/`、历史快照和备份文件不进入现行编号扫描范围。

## 6. 编号对照表

拟建立 `docs/2026-11-07_零件编号对照表.md`，作为唯一登记清单。建议字段如下：

| 字段 | 要求 |
| --- | --- |
| 编号 | 符合语法且在码表内；全表唯一 |
| 对象类型 | `零件`／`装配`／`骨架`／`契约`／`排版`／`试验` |
| 零件或文档中文名 | 自描述，使用当前结构词汇 |
| FCStd 相对路径 | 从仓库根目录开始；现行主文件必须存在 |
| 所属模块 | 使用已登记模块码 |
| 状态 | `在用`／`停用`；停用不删历史行 |
| 备注 | 外购示意、历史混合文档、替代关系等必要说明 |

登记表规则：

- 零件源件和装配必须填写编号；不领号文档的编号栏统一填 `—`，不得留空造成歧义；
- 一份主 FCStd 只登记一次；历史混合文档包含多个零件时，在备注标明尚未拆分的覆盖范围，不复制多行共享同一编号；
- 不登记数量作为编号定义的一部分；数量由装配和 BOM 管理；
- 文件移动时更新路径并检查 XLink，不因移动本身换号；
- 停用编号保留原路径、名称和替代关系，**不得回收给新零件**；
- 备份目录、导出文件和临时试参文件不得借登记获得正式编号。

## 7. 模型内锚点与 Label

### 7.1 零件源件

零件号写在代表该零件的根对象 `Label` 首段，格式为：

```text
<零件号><空格><中文零件名>
```

示例：

```text
ZJ-XH-01 下环上层板
```

- 对 PartDesign 零件，优先锚定主 Body；
- 对非 PartDesign 单实体零件，锚定代表最终零件的根对象；
- 文档内参数 Sheet、基准、草图、中间特征不重复带零件号；
- 内部 `Name`、参数 `Alias` 和表达式不因挂编号而批量修改；
- FCStd 文件名可继续保持 PascalCase，**不要求为加入编号而重命名文件**。

### 7.2 装配 Link

装配 Link 的 `Label` 首段带被引用零件号；重复件在末尾增加实例序号：

```text
HJ-01 桁架铝杆 #01
```

装配容器使用装配号和中文装配名。普通基准、草图和特征仍遵守中文自描述规则，不强制带装配号。

### 7.3 历史模型

现有历史混合文档保持现状，不为挂编号而重建或拆分几何。只有实际触碰相关零件或执行经确认的增量整理时，才补充根对象锚点，并同步检查 Link、XLink、表达式和实体有效性。

## 8. 参数表与应用层引用

参数表拟增加“使用零件”列，用于说明参数作用对象，不承担数量或装配位置定义。

允许填写：

- 一个或多个已登记编号；
- 已登记的集合词，如“全部木板件”；
- 不适用时填 `—`。

多个编号建议统一用 `、` 分隔，例如 `ZJ-XH-01、ZJ-XH-02`。不得填写未登记简称、临时文件名、模糊范围或 `HJ-01～08` 这类不可直接校验的展开式。

集合词也必须封闭登记，并明确其展开依据。例如“全部木板件”应由登记表中的材料或备注标签可判定，不能由 AI 按零件名称猜测。

参数表中的“使用零件”只表达参数适用范围：

- 不在该列填写数量和实例号；
- 不用该列代替 BOM；
- 参数变化导致适用范围变化时，先更新参数表，再按要求回写模型；
- 新零件尚未登记时，不得先用临时编号填满该列。

## 9. 变更、版本与停用纪律

### 9.1 先登记，后使用

正常新增顺序：

```text
查码表和登记表 → 确认无重号 → 登记编号与主路径 → 创建／修改模型 → 回填应用层引用 → 校验
```

新增大模块码、小模块码或集合词时，必须先经用户确认。仅分配已启用模块内的新序号，不改变码表，但仍须遵守先登记后使用。

### 9.2 编号不等于版本号

- 普通设计迭代由 Git 和必要的修订记录管理，不把版本、日期或批次拼入零件号；
- 文件改名或路径移动不自动导致换号；
- 几何、材料或接口变化后是否换号，按是否仍可互换判断；不能互换的新定义应使用新编号，并保留旧号的停用／替代记录；
- 已完成加工或已交付定义的换号属于高风险变更，必须由用户确认并检查 BOM、DXF、装配和试验记录；
- 旧号永久停用，不循环复用。

### 9.3 与参数发布纪律一致

码表和登记规则属于冻结类决策。正式变更顺序为：

```text
用户确认 → 更新 AGENTS／码表和编号对照表 → 更新 SKILL／wiki → 回写参数表、模型和交付物 → 回归检查
```

若只是登记表路径修正或新增普通零件号，不涉及码表变更，可按实际工作增量登记，但不得借路径修正偷偷换号。

## 10. 机器校验闭环

建议分成两个脚本层级，避免所有检查都依赖 FreeCAD：

1. **快速文本／路径检查**：使用 Python 标准库检查 Markdown 登记表、文件路径和应用层引用；
2. **模型检查**：使用项目约定的 `freecadcmd` 检查 FCStd 根对象 Label、装配 Link 和模型有效性。

建议后续增加 `tools/check_part_numbers.py`，至少检查：

- 编号符合正则，序号不是 `00`，模块码在封闭清单内且不含 `I／O`；
- 编号唯一，不存在一号多主文件或同一主文件多正式编号；
- 所有登记路径存在，所有现行零件源件均已登记；
- 未编号文档具有明确类型，扫描时排除 `backup/`、历史快照和 FreeCAD 备份文件；
- 参数表“使用零件”中的编号和集合词均已登记；
- 停用号未在新模型或新引用中重新启用。

模型回归脚本至少检查：

- 源件根对象 Label 首段与登记编号一致；
- 装配 Link 的编号与其实际引用源件一致，重复件实例号不重复；
- 不存在带同一零件号的多个独立源件根对象；
- 挂编号后 recompute、XLink、草图、有效实体和关键参数回归通过。

检查失败时的处理：

- 任一重号、未登记码、失联路径或模型锚点不一致均停止批量发布；
- 报告具体编号、路径和冲突双方；
- 不由脚本自动改号、自动合并重复件或覆盖用户并发修改。

## 11. 验收清单

涉及零件编号的工作完成后，至少确认：

- [ ] 格式正确，模块码和集合词均在封闭清单内；
- [ ] 编号唯一，源件路径唯一且存在；
- [ ] 同种多件未重复发号，不同零件未共用编号；
- [ ] 零件、装配、实例和不领号文档没有混用；
- [ ] 模型根对象及装配 Link 与登记表一致；
- [ ] 参数表及其他应用层只引用已登记编号或集合词；
- [ ] 停用号未复用，历史映射未删除；
- [ ] 模型修改已执行 recompute、实体、草图、接口、干涉及关键参数回归；
- [ ] 文本检查脚本和模型检查脚本均无未解释错误。

## 12. 建议落地顺序

为避免出现“强制查表但登记表尚不存在”的空窗，前两步应在同一批变更中完成：

1. **规则与首表同时落地**：用户确认码表和本规范后，更新 `AGENTS.md`、FreeCAD 建模技能，建立编号对照表并盘点当时全部现行 FCStd；
2. **校验先行**：先实现登记表和路径检查，再允许批量引用编号；
3. **参数表回填**：增加“使用零件”列，只回填已确认映射，不猜测历史混合文档的内部零件；
4. **模型增量挂号**：优先新源件和当前仍在详细设计的零件，再逐步处理历史模型；每批执行 FreeCAD 回归；
5. **交付物联动**：后续 BOM、单件工程图和加工清单使用零件号；整板 DXF 保持整板交付逻辑，通过对应排版文档或加工清单列出所含编号，不强求一块整板只对应一个编号；
6. **wiki 收尾**：在现有命名规范中补充原因、示例和导航，并同步 `wiki/index.md`、`wiki/log.md`，不复制第二份编号清单。

前两步完成后，新零件即受编号约束；历史模型可处于“已登记、待挂 Label”的过渡状态，但必须显式记录，不能默认视为全部合规。

## 13. 待用户确认的最小决策集

正式发布前只需先裁决以下事项，不要求一次决定所有零件号：

1. 大模块码 `Z／D／ZJ／HJ／DB／TY` 的中文含义，以及 `CD／GT` 的预留状态；
2. 是否采用“同种多件共用零件号，`#nn` 仅作实例号”的规则；
3. 是否同意零件号只锚定零件根对象和装配 Link，不扩展到所有草图与特征；
