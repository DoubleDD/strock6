# 仓库目录结构迁移计划

- 创建日期：2026-11-07
- 状态：已完成（2026-11-07；实际结果见第九节）
- 执行前提：用户审核通过，且 FreeCAD、备份监控及其他正在使用相关文件的进程均已正常退出
- 任务性质：仓库结构维护，不改变望远镜设计参数、模型几何、模块边界或阶段任务状态

## 一、目标与原则

将当前仓库整理为适用于“CAD 模型＋自动化脚本＋测试＋文档”的软件工程式目录结构，但不套用 FastAPI 等 Web 项目的分层，也不引入 Python 包发布结构。

核心约定：

- `cad/` 是正式 FreeCAD 模型及模型契约的唯一入口。
- `src/` 存放工具和自动化脚本源码。
- `tests/` 存放自动化测试、测试专用模型及测试输入，与 `src/`、`cad/` 平级。
- 现有模型模块已经划分合理，只在模块外增加 `cad/` 一层，不重命名模块或 FCStd 文件。
- 产品装配模型属于正式产品定义，不因为名称为 `Assembly` 就归入测试目录。
- 本轮只做目录迁移、必要的路径修正和文档同步，不顺带重构设计逻辑或引入新的构建体系。

│   ├── 00_TotalAssembly/           # 正式总体骨架与总装
│   ├── 01_Base/

│   │   └── Interfaces.FCStd

├── src/                            # 工具与自动化源码
│   ├── tools/                     # 通用项目工具
│   │   └── freecad_backup_monitor.py
│   └── freecad/                   # FreeCAD 自动化脚本
│       ├── T10_build_m_layout.py
│       └── T10_extract_m_pairs.py

├── tests/                          # 自动化验证

│   │   └── T10_rotation_expression_test.py

│       └── cad/                   # 测试装配、最小样例和故障样例
│
├── docs/                           # 当前设计与管理文档，位置不变

不建立 `src/strock6/` 同名包层，不添加 `__init__.py`、`pyproject.toml` 或 Python 打包配置，不引入 `api/`、`routers/`、`services/` 等 Web 项目目录。测试代码放在 `tests/`，作为“源码位于 `src/`”规则的常规工程例外。

## 三、模型与测试的边界

### 正式产品模型

以下内容是产品定义，继续留在 `cad/` 对应模块：

- 总体骨架、正式总装和模块装配。
- 独立零件源件。
- 跨模块接口契约。
- 通用件和未来扩展模块。

例如 `TotalAssembly.FCStd`、`LowerRingAssembly.FCStd` 均为正式装配模型，不属于装配测试。

### 模型测试

`tests/` 用于验证模型是否满足规则，主要包括：

- 文档与参数：重新打开、recompute、XLink、参数回归。
- 零件：有效实体、实体数量、草图冲突／冗余、关键尺寸。
- 装配：基准对齐、静态干涉、间隙和拆装空间。
- 运动：行程、限位和运动包络。
- 测试装配：在 `tests/fixtures/cad/` 中构造专用 FCStd，用于最小复现、边界条件或故障样例，不混入正式总装。

现有 CNC 试片、主镜座套合试环及实物试验记录本轮不跨模块搬迁，仍分别保留在原模型模块和 `TODO/` 中。后续如需建立统一的实物验证资产体系，应另行评审，不在本轮扩大范围。

测试产生的临时结果不提交；需要长期保存的人工验证结论仍按现有规则进入 `TODO/` 或 `docs/`。

| `.pi/T10_extract_m_pairs.py` | `src/freecad/T10_extract_m_pairs.py` | 分析工具，仅做路径适配 |
| `.pi/T10_inspect_current.py` | `tests/freecad/T10_inspect_current.py` | 只读模型检查 |

## 五、实施步骤

### 1. 执行前保护与基线记录

1. 确认用户已批准本计划。
2. 确认 FreeCAD、备份监控及其他相关进程已正常退出；不强制终止进程，不在文件写入期间迁移。
3. 记录当前 Git 状态、文件清单和 FCStd 校验值，作为迁移后对照。
4. 保留现有未提交和未跟踪内容，不提交、不推送、不清理无关改动。

### 2. 移动模型与代码

1. 建立 `cad/`、`src/`、`tests/` 及上述子目录。
2. 按迁移映射移动目录和文件，不复制出多套模型真值。
3. 不重命名任何现有模型模块或 FCStd 文件。
4. 不修改设计参数、模型几何、接口公式或模型 Label。

### 3. 修正代码与配置路径

1. 更新备份监控脚本的项目根目录定位。
2. 将备份监控默认扫描范围设为 `cad/`，默认归档目录设为 `cad/backup/`，保持归档后的模块相对结构，避免生成重复的 `cad/backup/cad/...` 层级。
3. 更新现有 FreeCAD 脚本中的模型路径，统一指向 `cad/`；只读检查脚本不得新增保存行为。
4. 更新 `.vscode/tasks.json` 中底座总成和备份监控脚本路径，并同步任务说明。
5. `.gitignore` 增加 `__pycache__/`、`*.py[cod]` 等 Python 缓存规则。
6. `.gitattributes` 的 Git LFS 规则不受目录深度影响，无需修改。

### 4. 同步活动文档

1. 更新 `AGENTS.md`、项目 FreeCAD 建模技能和相关 wiki 当前规范中的目录约定。
2. 更新 `docs/`、`TODO/` 中实际指向模型的 Markdown 链接。
3. 检查 `wiki/index.md` 和 `wiki/log.md`；在日志中记录本次目录迁移，必要时更新导航。
4. 在实施计划中记录“仓库目录结构迁移”的维护日志和最近更新日期，不改变 T09～T17 的设计任务状态。
5. `raw/` 以及历史日志中的旧路径属于历史记录，不批量改写。
6. 执行后更新本计划的执行状态、验证结果和遗留事项。

## 六、验证方案

### 文件与链接完整性

- 对照迁移前后的文件清单和 FCStd 校验值，确认模型内容未发生变化。
- 检查所有应迁移文件均存在，原位置不再残留第二份模型真值。
- 检查当前文档和配置中的活动链接；`raw/` 和明确保留的历史日志除外，不应遗漏旧路径。
- 检查 Git 状态，确认没有迁移范围之外的文件变化或测试生成物。

### FreeCAD 模型回归

使用项目指定的 `freecadcmd` 对全部当前 FCStd 逐份只读重开并执行 recompute，不保存模型，检查：

- ZIP／FCStd 文件完整性。
- XLink 目标存在且无断链。
- 无新增对象错误或无效状态。
- 零件实体有效，实体数量不变。
- 草图无新增冲突或冗余。
- 正式装配链接和接口保持有效。
- 迁移前后未产生意外几何变化。

本验证只证明目录迁移未破坏模型，不据此关闭尚待实物验证的设计任务，也不把既有设计问题误报为迁移问题。

### 脚本与测试

- 对全部 Python 文件做语法检查，避免生成缓存污染仓库。
- 使用临时目录和样例文件验证备份监控的扫描与归档行为，不在真实模型目录进行试验性归档。
- 运行只读 FreeCAD 检查脚本，确认新路径可用。
- 不主动执行会修改并保存模型的 `T10_build_m_layout.py`；其验证仅限不触发模型写入的检查。
- 确认 VS Code 相关任务指向新路径。

## 七、完成判据

同时满足以下条件，目录迁移才可标记为完成：

1. 目标目录结构与迁移映射一致，模型模块内部未被重排。
2. 所有 FCStd 内容和校验值保持不变，只读重开、recompute 和 XLink 检查通过。
3. 当前代码、VS Code 配置和文档链接均使用新路径。
4. 备份监控在临时样例上的行为正确，默认目录指向 `cad/` 与 `cad/backup/`。
5. 未引入 Python 打包或 Web 项目结构，未改变设计参数和阶段任务状态。
6. 实施计划、wiki 日志及本计划已记录实际执行和验证结果。

任一模型链接或完整性检查失败时，停止后续操作并保留证据；只回退本轮迁移产生的改动，不覆盖用户或其他进程的并发修改。
