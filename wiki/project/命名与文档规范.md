# 命名与文档规范

文档层级镜像产品树（BOM 树），递归同一模式：

**每个零件一份零件图 → 每个模块（含小模块）一份组装图 → 组装图只做 App::Link 装配，不画新几何。**

词汇纪律：**目录名、组装图文件名、角色描述必须用同一套词**——目录名 = 角色英文直译（如桁架 → `Truss`），组装图 = `<Module>Assembly.FCStd`。不引入与实际结构不符的行话（本设计无镜筒，LTA/UTA 类词汇已弃用）；当前主镜座支撑方案不使用“主镜箱”作为功能模块名。

## 文件命名

| 类型 | 模式 | 示例 | 位置 |
| --- | --- | --- | --- |
| 零件图 | `<PartName>.FCStd` | `RockerBase.FCStd`、`OctRing_A.FCStd` | 所属模块或子总成的 `Parts/` |
| 组装图 | `<Module>Assembly.FCStd` | `TrussAssembly.FCStd`、`BaseAssembly.FCStd` | 模块目录根部 |
| 小模块 | 子目录 `<SubModule>/`（目录名 = 组装图去 `Assembly` 后缀） | `cad/04_TopEnd/SubAssemblies/Secondary/` | 模块 `SubAssemblies/` 内 |
| 标准件 | 同零件图 | 螺栓、轴承 | `cad/90_CommonParts/Standard/` |
| 自制通用件 | 同零件图 | 跨模块共用自制件 | `cad/90_CommonParts/SharedParts/` |
| 契约层 | `Interfaces.FCStd` | — | `cad/91_Interfaces/` |

- 正式产品模型统一放在 `cad/`；工具和自动化源码放在 `src/`；自动化测试和测试专用模型分别放在 `tests/` 与 `tests/fixtures/cad/`
- 产品装配是正式模型，留在 `cad/`；只有专为验证建立的测试装配才进入测试目录
- 模块专属零件放 `Parts/`，下一级总成放 `SubAssemblies/`，TechDraw 源文件放 `Drawings/`
- 一个文件只画一个零件（源件）；多处使用用 App::Link 实例化，不复制实体
- 外购件（调焦座、M42 延长筒）只建示意模型，文件内标注"外购·示意"
- PascalCase；`_` 仅用于同模块内区分变体（如 `OctRing_A/B`、`Pad_P_L`）

## 契约引用规则

各模块参数表以**相对路径** XLink 引用 `cad/91_Interfaces/Interfaces.FCStd`；具体相对深度由引用文件所在位置计算。**文件移动或层级变化后必须重连引用**（改 zip 内 Document.xml 的 `<XLink file="…"/>` 或在 GUI 重连）；同级改名不影响相对引用。

## 过渡态

现有 5 份模块文档（BaseAssembly、PrimarySupportAssembly、TrussAssembly、SecondaryAssembly、UpperRingAssembly）为历史文件，零件体与装配体混在单文档内，**保持现状使用**；今后新零件一律单独建档、组装图以 Link 引用，逐步演进到纯规范形态。当前结构已明确不设独立主镜箱；原 `02_MirrorBox/MirrorBoxAssembly.FCStd` 已于 2026-11-06 改名为 `02_PrimarySupport/PrimarySupportAssembly.FCStd`（目录、文档 Label 已同步，XLink 相对路径深度不变无需重连）。文档内部参数表沿用历史内部名 `Params_R180/M01…M06`（FreeCAD 内部名不可改），对应关系见改名映射。

## 版本管理

- `*.FCStd / *.step / *.stl` 走 Git LFS（`.gitattributes` 已配置，FCStd 另加 `lockable`）
- FreeCAD 备份/锁文件（`*.FCStd1`、`*.FCStd.lock` 等）已在 `.gitignore` 忽略
- 导出文件统一放 `exports/`，按 `step/`、`stl/`、`bom/`、`drawings/` 分类，文件名带模块前缀（如 `exports/step/01_Base_BaseAssembly.step`）；不设置模块级 Export
